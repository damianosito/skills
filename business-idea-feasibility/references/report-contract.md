# Report Contract

Use this structure for every full feasibility report. Do not omit sections. Adapt depth to the idea while keeping the headings and decision logic intact.

# Business Idea Feasibility Study

## 1. Idea Summary

Summarise the idea in plain English. Then write:

> For [target user] who struggles with [problem], this product helps them [outcome] by [method or differentiator].

## 2. Assumptions Made

List material assumptions caused by missing information. Include geography, buyer, pricing, platform, founder resources, and scope where relevant.

## 3. Traffic-Light Verdict

Give exactly one:

- Red - Abandon / Park
- Amber - Proceed with Caveats
- Green - Proceed

Explain the decision directly in three to six sentences. Name any fatal flaw or conditions that control the verdict.

## 4. Scorecard

Score each category from 1 to 5:

| Category | Score /5 | Reason |
|---|---:|---|
| Problem severity |  | Is the pain urgent and costly enough? |
| Market demand |  | Is there credible evidence of demand and payment? |
| Competition gap |  | Is there room for a reachable new entrant? |
| USP strength |  | Is the difference meaningful and hard to dismiss? |
| Monetisation potential |  | Can revenue exceed acquisition and delivery costs? |
| Build feasibility |  | Can the core value be built and operated leanly? |
| Startup cost attractiveness |  | Are setup and working-capital needs manageable? |
| Go-to-market feasibility |  | Can the first customers be reached affordably? |
| Legal/compliance safety |  | A low score means high risk. |
| Defensibility |  | Can the advantage compound or resist copying? |
| Founder fit |  | Does the user's actual context improve execution? |
| Speed to validation |  | Can the key assumptions be tested quickly? |
| **Total** | **/60** |  |

Scoring anchors:

- `1`: very weak or very high risk
- `2`: weak
- `3`: mixed or uncertain
- `4`: strong
- `5`: excellent

## 5. Market and Competitor Scan

Cover:

- direct competitors;
- indirect competitors and substitute behaviour;
- incumbent advantages and saturation;
- what competitors do well;
- source links and research date for changeable claims.

Always include these labelled subsections:

### Competitor Weakness Map

For each competitor cluster, state weaknesses, recurring complaints, pricing or UX gaps, trust and support gaps, underserved audiences, and switching barriers. Do not infer complaints from feature absence alone.

### Missing Market Needs

Separate:

- `Evidence-backed needs`: repeated complaints, paid workarounds, active demand, or measurable friction.
- `Speculative needs`: plausible improvements without reliable willingness-to-pay evidence.

### Wedge Assessment

Judge whether each gap is painful, valuable, reachable, technically feasible, defensible, and suitable for this user. State why the proposed wedge can or cannot support a product.

### Brutal Conclusion

Say whether the gap is a real opening, a narrow lifestyle opportunity, a feature, or weak differentiation in a crowded market.

## 6. Market Demand and Potential Share

Analyse:

- demand evidence and its quality;
- buyer, user, and first beachhead niche;
- TAM, SAM, and SOM only when defensible data exists;
- bottom-up first-year customer potential;
- realistic first 10 and first 100 customers;
- whether this is likely a tiny tool, lifestyle business, scalable startup, or weak opportunity.

Never disguise invented precision as market sizing. Prefer a transparent bottom-up range.

## 7. Unique Selling Point Analysis

State:

- proposed USP;
- whether it is actually unique;
- what to narrow, remove, or reposition;
- incumbent copy risk;
- the strongest defensible version of the proposition.

## 8. Build Complexity and Cost

Include:

- smallest MVP feature set;
- features to delay;
- manual/concierge alternative;
- suggested stack or delivery approach;
- build difficulty and time;
- main technical and operational risks.

Use a granular cost table:

| Cost item | Lean estimate | Type | Assumption or trigger |
|---|---:|---|---|
| Build/design |  | One-off |  |
| Legal/compliance |  | One-off/annual |  |
| Core software/hosting |  | Fixed monthly |  |
| APIs/data/AI |  | Fixed + variable |  |
| Payments |  | Per transaction |  |
| Support/moderation |  | Variable |  |
| Marketing/testing |  | One-off/monthly |  |

Then show:

- fixed monthly MVP cost;
- variable unit cost and contribution margin;
- heavy-user or low-conversion sensitivity;
- rough break-even arithmetic;
- high-risk costs that need supplier quotes or legal advice.

Use ranges and state currency, geography, tax treatment, and whether founder labour is excluded.

## 9. Monetisation

Recommend:

- revenue model and price range;
- free versus paid boundary;
- likely payment resistance;
- fastest route to first revenue;
- unit economics and likely LTV/CAC concern;
- why the buyer would pay instead of using a substitute.

## 10. Legal, Ethical, and Compliance Risks

Address what is relevant: privacy, data security, AI disclosure, copyright, scraping, platform terms, regulated advice, consumer protection, safeguarding, vulnerable users, employment, accessibility, misinformation, defamation, moderation, payments, tax, insurance, and human oversight.

Give one legal-risk rating: `Low`, `Medium`, `High`, or `Very High`.

Do not present this analysis as legal advice. Identify where qualified counsel is needed.

## 11. Go-to-Market Plan

Give:

- first target niche and buyer;
- where those people already gather;
- first three channels and why they fit;
- best landing-page or fake-door test;
- direct outreach test;
- content/SEO angle;
- partnership angle where relevant;
- path to first 10 paying users;
- path to first 100 paying users;
- expected sales-cycle or CAC difficulty.

## 12. Kill Criteria

List numerical, time-bound reasons to abandon or radically reposition. Examples:

- fewer than 10% of well-targeted prospects agree to an interview;
- fewer than 3 of 20 qualified interviews describe the problem as frequent and costly;
- no deposits, pre-orders, letters of intent, or paid pilots after a defined test;
- required acquisition cost exceeds plausible gross profit;
- compliance or integration makes the lean MVP impossible;
- users like the concept but will not change behaviour or pay.

Customise thresholds to the channel and ticket size.

## 13. 7-Day Validation Plan

Provide one concrete action per day:

- Day 1: narrow the niche, painful job, and one-sentence promise.
- Day 2: verify competitors, pricing, complaints, and substitutes.
- Day 3: create a landing page, mock-up, or concierge offer.
- Day 4: contact qualified target users through a reachable channel.
- Day 5: run problem interviews or concierge trials.
- Day 6: test payment with a deposit, pre-order, paid pilot, or credible commitment.
- Day 7: compare evidence against kill criteria and reissue the verdict.

Do not count compliments, waitlist emails, friends' opinions, or social likes as payment evidence.

## 14. MVP Recommendation

Describe:

- must-have features;
- nice-to-have features to delay;
- manual concierge version;
- no-code or low-code route where suitable;
- what not to build;
- one core assumption the MVP is designed to test.

## 15. Final Recommendation

End with exactly one of these stems and complete it directly:

- `Abandon this idea for now because...`
- `Do not build yet. Validate these assumptions first...`
- `Proceed with a very narrow MVP focused on...`

Add a short TL;DR only when requested or when the report is unusually long.
